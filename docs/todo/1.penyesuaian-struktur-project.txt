Tujuan penyesuaian:
Saya ingin project ini dipindahkan dari struktur yang lebih sederhana menjadi struktur yang lebih siap berkembang, dengan aturan berikut:
- `modules/` berisi fitur bisnis
- `platform/` berisi komponen teknis/infrastruktur
- `shared/` berisi utilitas lintas modul
- tetap mudah dipahami pemula
- tetap menjaga separation of concern
- jangan menambahkan abstraction yang belum perlu

Project harus tetap memiliki fitur berikut:
1. Auth JWT
2. CRUD products
3. Middleware
4. Validation
5. Logging
6. Redis cache
7. Swagger
8. Docker Compose
9. SQL migration manual
10. Seeder
11. Error handling / exception handling
12. Integration test

Penyesuaian yang saya inginkan:

A. REFACTOR STRUKTUR
- pindahkan feature `auth` ke `internal/modules/auth`
- pindahkan feature `product` ke `internal/modules/product`
- bila tabel `users` dipakai lintas feature, buat `internal/modules/user`
- pisahkan kode teknis ke `internal/platform`
- pisahkan helper umum ke `internal/shared`
- update semua import path agar sesuai dengan module `github.com/niamfauzi/go-starter`

B. PENYESUAIAN PENAMAAN FILE
Saya ingin penamaan file mengikuti struktur siap berkembang:
- `handler.go` bisa diubah menjadi `delivery_http.go`
- `model.go` bisa diubah menjadi `entity.go`
- request/response struct dipisah ke `dto.go`
- helper hashing password dipisah ke `password.go`
- JWT logic dipisah ke `jwt.go`
- context auth dipisah ke `context.go`
- cache helper product dipisah ke `cache.go`
- mapper entity <-> response dipisah ke `mapper.go`

Tapi:
- jika ada file yang tidak perlu dipisah, jelaskan alasannya
- jangan memecah file hanya demi terlihat kompleks

C. ATURAN DESAIN
Terapkan aturan berikut:
- `modules/` hanya berisi logic bisnis per fitur
- `platform/` hanya berisi hal teknis seperti DB, Redis, logger, HTTP server, middleware
- `shared/` hanya berisi utilitas yang dipakai lintas modul
- 1 tabel database = 1 entity utama
- jangan duplikasi entity GORM yang sama di banyak modul
- jika modul lain hanya butuh sebagian field, gunakan DTO / projection struct
- semua query tetap tenant-aware
- tenant diambil dari header `X-Tenant-Id`
- JWT tetap dipakai untuk endpoint terproteksi
- migration tetap SQL manual, bukan AutoMigrate

D. YANG HARUS KAMU JELASKAN
Saya ingin penjelasan yang sangat ramah pemula:
- kenapa `auth` dan `product` dipindah ke `modules/`
- kenapa `platform/` dipisah dari `modules/`
- kenapa `shared/` dibutuhkan
- kapan sesuatu harus masuk `modules/`, `platform/`, atau `shared/`
- kenapa entity utama tidak boleh diduplikasi di banyak modul
- kapan perlu membuat DTO, mapper, atau projection
- kenapa struktur ini lebih siap berkembang
- apa trade-off dibanding versi sederhana
